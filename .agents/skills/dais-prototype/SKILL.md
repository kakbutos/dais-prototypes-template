# Прототип из макета

Применяй общие правила `AGENTS.md`, включая выбор формата и соразмерную проверку UI.

## Место изменения и исходник

Для нового экрана выполни `npm run prototype:new -- <slug> "Название" --reference "/путь/макет.png"`: команда создаёт пустой React-компонент и сохраняет PNG в `.references/<slug>/`. Без доступного файла опусти --reference. Для нескольких исходников используй отдельные имена. Снимки реализации сохраняй отдельно в `.local/checks/<slug>/`.

Если пользователь просит встроить элемент в названный прототип, меняй его и связывай элемент со сценарием, не создавай отдельную страницу. Специфичную логику держи в варианте или передавай через props: изменение общего recipe затронет всех потребителей.

Открой исходный PNG; кратко зафиксируй путь, размер, секции, значения и состояния. Мелкие подписи рассмотри увеличенно или отдельными областями доступным инструментом. Заметки не заменяют исходник при сверке. Если вложение видно, но сохранить нельзя, сообщи об этом. Если доступ потерян, запроси исходник или согласуй работу по описанию без утверждения о визуальном сходстве.

Сохраняй видимый состав и начальное состояние. Не додумывай обязательность полей, блокировки и панели действий. Обрезанный край не доказывает наличия или отсутствия элементов за кадром; уточняй только неизвестное, блокирующее реализацию.

## Найди нужный API

Используй доступные Dais MCP search_components/get_component/get_component_props по выбранным компонентам; для таблицы — list_features/get_feature/get_feature_examples по нужной фиче. Карта типов и известная ошибка карточки TableCanvas: `docs/COMPONENTS.md`. Для табличной задачи начни с работающей конфигурации в `src/recipes/Collection.tsx`; для формы подбирай компоненты формы.

Ищи конкретные свойства в `.d.ts`, не читай большие файлы целиком и не выводи собранные JS с base64. Перед выводом об отсутствии экспорта проверь реэкспорты. Не угадывай props и имена иконок.

Если MCP недоступен, проверь настройки и `npm run mcp:check`, затем продолжай по установленным типам. Успех команды подтверждает сервер, а не подключение инструментов к текущей сессии; сообщи, если работал без них. Не меняй зависимости ради подключения MCP.

## Собери экран

Используй публичные импорты `@daisforge/ui`, `/components/TableCanvas`, `/icons`, `/tokens`, `/utils`. В ячейках таблицы — Canvas.*, а не DOM-компоненты. Фичи добавляй по макету/запросу; каждое заявленное действие должно иметь наблюдаемый результат.

Композицию оформляй через styled-components, цвета — импортированными токенами. Вид компонентов задавай поддерживаемыми props, без переопределения внутренних стилей. Внешние размеры и отступы задавай контейнеру. Особенности canvas-цветов, размеров полей и общих провайдеров описаны в `docs/COMPONENTS.md`.

Для иконок используй библиотечные IconButton/EmbedIconButton или contentLeft/contentRight у Button. Название вроде `16/fill/Download` — подсказка для поиска, не гарантированное имя экспорта. Типографику макета сопоставляй с Dais: например, Body/BodyS N → BodyS или Typography variant="BodyS"; проверь доступность. У библиотечных текстовых слотов уже есть стиль: дополнительная типографика нужна только при подтверждённом расхождении.

## Сверь и передай результат

Следуй порядку проверки из AGENTS.md. Для просмотра без галереи используй `/?standalone=1#/<slug>`; размер области выбирай по исходнику, без фиксированной поправки на шапку. Сравни состав, порядок, состояния, размеры, типографику, иконки и обрезание, включая лишние элементы. HTML-экспорт уже не содержит оболочку галереи.

В итоге дай адрес варианта и кратко раздели визуальную сверку, проверенные действия и технические проверки; назови оставшиеся расхождения и непроверенное. Для передачи используй выбранный dais-export-html или dais-publish в рамках запроса пользователя.
