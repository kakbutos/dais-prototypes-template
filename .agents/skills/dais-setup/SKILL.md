# Подготовка Dais

Прочитай `docs/GETTING_STARTED.md` из корня проекта. Работай из папки с package.json `dais-prototypes-template`. Если проект ещё не скачан, помоги пройти создание собственной копии и clone по руководству; скачанный ZIP сам по себе не имеет Git remote для публикации.

Сначала определи ОС, оболочку и уже доступный клиент из окружения. Уточняй только то, чего нельзя определить. Проверь `node --version`, `npm --version`, `git --version`, `gh --version`; для локального старта нужны Node/npm, для полного процесса публикации также Git/gh. Node: 22.14+ из ветки 22 либо 24+. Не заменяй рабочие подходящие установки. На Windows при блокировке npm.ps1 используй npm.cmd или cmd.

Если чего-то нет, помоги установить по ветке macOS/Windows в руководстве: выполняй доступные действия в рамках запроса и прав, а нужные клики в установщике объясняй по одному шагу с проверкой результата. Не выдавай одну общую фразу «установите зависимости». Для ограничений корпоративного ПК дай конкретный список для ИТ, не обходи ограничения и не отключай проверку сертификатов. После установки перепроверь PATH в новом терминале/клиенте. Не запускай npm setup, пока Node/npm недоступны.

Если нужна подготовка GitHub, проверь `gh auth status`, `git remote -v` и настройки `git config user.name`/`user.email`. При отсутствии входа помоги запустить `gh auth login --hostname github.com --git-protocol https --web`, затем `gh auth setup-git --hostname github.com`. Пользователь сам завершает браузерный вход/2FA. Не запрашивай пароль, токен или одноразовый код в чате, не считай отправленную ссылку успешным входом: повтори auth status. Не меняй активный аккаунт или подпись коммитов без причины; недостающее имя/email уточни и задай локально для проекта. При запросе только локального запуска отсутствие GitHub-входа не блокирует работу. Подготовка не разрешает сама по себе публикацию.

1. Выполни `npm run setup`: npm ci, проектные конфиги MCP, копии skills, диагностика и реальные MCP-вызовы. Исходники Dais/Plasma/Glide скачивать не требуется.
2. При проблемах используй `npm run doctor` и `npm run mcp:check`. Не обходи peer-конфликты через force/legacy-peer-deps и не переключай пакеты на latest.
3. После настройки MCP перезапусти/попроси перезапустить клиент и пройти его штатную процедуру доверия проекту. Проверь доступный агенту `dais-ui` вызов `get_component` для `TableCanvas`: успешный smoke-тест сервера сам по себе не доказывает подключение клиента.
4. Запусти `npm run dev`, проверь страницу и дай фактический локальный адрес. Отдельно назови то, что ещё не проверено. Не называй подготовку завершённой, если установка, MCP или страница не работают.

Повторная подготовка сохраняет `src/prototypes`, другие MCP и настройки. Локальные конфиги исключены из git. Публикация по отдельному запросу описана в dais-publish и `docs/PUBLISHING.md`.
