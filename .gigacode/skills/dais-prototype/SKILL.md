# Прототип из макета

Для нового варианта выполни `npm run prototype:new -- <slug> "Название"`. Он создаёт независимый модуль в `src/prototypes/<slug>/index.tsx` с отдельным ключом хранения. Для изменения существующего варианта найди его модуль. Сохраняй остальные варианты.

Посмотри изображение доступным инструментом клиента. Если PNG не передан модели, сообщи ограничение и запроси описание/доступный вход; не заявляй о визуальной сверке. Раздели видимые факты и неизвестное поведение. Используй простой сценарий по умолчанию и назови существенные допущения; уточняй только детали, которые блокируют реализацию.

Перед выбором API используй MCP: `get_installation_guide`, `search_components`, `get_component`, `get_component_props`. Для таблицы — `list_features`, `get_feature`, `get_feature_examples`, при необходимости `get_type`. Данные должны соответствовать установленной версии. Примеры MCP могут ссылаться на отсутствующие Storybook-хелперы: сверяй импортируемые символы и бери самодостаточную композицию `src/recipes/Collection.tsx` как рабочую основу.

Используй готовые публичные компоненты Dais. Для табличных сценариев применяй TableCanvas; внутри канвасных ячеек — Canvas.*, а не DOM-кнопки. Функциональность таблицы бери из её API. Разметка и CSS приложения нужны для композиции и специфичного оформления. Прямое пожелание пользователя изменить библиотеку/подход имеет приоритет, но не меняй стек сам из-за отсутствующего примера.

Новый вариант может использовать общую композицию с props. Если нужна уникальная логика или оформление, создай файлы внутри его папки: изменение общего recipe влияет на все использующие его варианты. Данные для демо должны показывать поиск, группировку и редактирование. Не добавляй неработающие кнопки; у каждого заявленного действия должно быть наблюдаемое последствие.

Проверь `npm run build`, затем открой страницу и проверь затронутые сценарии, console errors, сравни с PNG при его размере. Если браузерного доступа нет, сообщи границу проверки. Для базовой композиции доступен `npm run test:browser` после `npx playwright install chromium`. Сохрани изолированное состояние варианта и возможность сбросить демо. Публикуй только по запросу, по навыку dais-publish.

В ответе дай адрес варианта, работающие сценарии и непроверенные/неподдержанные детали. Не называй результат точной копией без визуальной проверки.
