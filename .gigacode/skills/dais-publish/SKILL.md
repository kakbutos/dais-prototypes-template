# Публикация прототипов

Запрос «опубликуй» разрешает необходимые commit/push/deploy в установленный репозиторий проекта. Он не разрешает создавать публичный репозиторий, если аудитория и владелец ещё неизвестны: сначала подготовь и проверь приложение, затем уточни только недостающие параметры. Не меняй аудиторию существующего репозитория без запроса.

1. Прочитай `docs/PUBLISHING.md`. Проверь `git remote -v`, текущую ветку и `git status`. Если пользователь клонировал исходный шаблон, убедись, что origin указывает на предназначенный ему репозиторий. Не пушь в чужой шаблон.
2. Выполни `npm run build`, `npm test`, `npm run mcp:check`; для изменений интерфейса — браузерную проверку. Проверь GitHub CLI, `gh auth status`, подпись коммитов и авторизацию Git; недостающие шаги пройди по `docs/GETTING_STARTED.md`. Не запрашивай и не сохраняй токены в коде или чате.
3. `npm run publish:check` проверяет репозиторий и Pages. При первой публикации `npm run publish:setup` включает Pages с GitHub Actions в этом репозитории. Если прав нет, дай точный шаг из инструкции. Не обходи ограничения аккаунта/организации.
4. Просмотри diff, добавь только файлы прототипа и необходимые сопутствующие изменения. Не включай локальные конфиги MCP, node_modules, credentials и посторонние пользовательские файлы. Создай описательный commit и push. Workflow публикует main. Если работа идёт в другой ветке, следуй принятому процессу PR; не делай force-push и не сливай несогласованные изменения.
5. После push в main выполни `npm run publish:wait`. Он проверяет запуск для текущего commit, ждёт до 10 минут и проверяет HTTP-ответ Pages. При ошибке прочитай `gh run view <id> --log-failed`, исправь конкретную проблему. После двух неуспешных исправлений одной причины сообщи блокер, не запускай бесконечные повторные публикации.
6. Открой опубликованный вариант в браузере, если он доступен. Верни URL вида `https://<owner>.github.io/<repo>/#/<slug>` и статус проверки. Успешный push сам по себе не означает успешный deploy.

Опубликованный frontend содержит демонстрационные данные из репозитория. Изменения посетителя живут только в памяти открытого варианта и сбрасываются при его закрытии/перезагрузке. Для общего начального состояния внеси данные в исходники и опубликуй заново.
